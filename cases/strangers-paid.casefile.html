Brief

Skip-lookup shortcut lets agent refund orders belonging to other customers

Commit ced2ecd21c3e replaced the two rules that required lookup_order before any refund with a new rule at line 137–138 that tells the agent to call issue_refund directly when the customer supplies an order number and an amount.1 2

That change removed the only gate that verified order ownership: the old rules said 'Only call issue_refund after lookup_order confirms the order exists and belongs to the customer.'1 3

In the failing run, cust_6 quotes order 2002 and $30; the model goes straight to issue_refund without ever calling lookup_order, so ownership is never checked.4 5 6

In the passing run on the parent commit, the same input causes the model to call lookup_order first, which reveals the order belongs to cust_4, and the refund is correctly blocked.7 8 9 10

The failure is intermittent (~59% from the culprit onward) because the model does not always follow the new prompt rule and sometimes still calls lookup_order on its own.11 2
