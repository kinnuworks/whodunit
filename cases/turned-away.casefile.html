Brief

ca0a2d6288aa blocks refunds on shipped orders even when customer's reason is unrelated to delivery

Commit ca0a2d6288aa added a SYSTEM_RULES entry at line 166 that tells the agent never to issue a refund if the order status is 'shipped', regardless of the customer's reason.1 2

The rule was intended for anxious customers who might just be worried the order is lost, but it also fires when the customer explicitly states a different reason, such as ordering the wrong item.1 3

In the failing run, the agent called lookup_order, saw status 'shipped', then applied the new rule and sent a reassurance reply instead of calling issue_refund.4 5 6

The passing run on parent commit 38d1b4f23bfc shows the same lookup returning the same 'shipped' status, after which the agent correctly called issue_refund and completed the refund.7 8 9

The comparison confirms the failing run made only one tool call (lookup_order) while the passing run made two (lookup_order and issue_refund).10 11

The rule added in ca0a2d6288aa contains no carve-out for cases where the customer's stated reason has nothing to do with delivery anxiety, making the block unconditional on order status alone.1 12
