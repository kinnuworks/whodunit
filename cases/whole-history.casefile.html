Brief

ced2ecd21c3e removes ownership check by letting agent skip lookup_order

Commit ced2ecd21c3e replaced the two rules that required lookup_order to confirm ownership before any refund with a rule telling the agent to call issue_refund directly whenever the customer supplies an order number and an amount. 83585e74ced2ecd21c3e

The request at bfbe27725663 asked for a shortcut only when the customer had already given both pieces of information, but the commit removed the ownership-verification gate entirely, which is where the two diverge. 83585e74bfbe27725663

In the failing run, cust_6 quotes order 2002 with $30; the agent goes straight to issue_refund at span 56f402ce without ever calling lookup_order, so it never learns that order 2002 belongs to cust_4. 47e39d7c784a56f402ce5dedf0ce

In the passing run at commit 92122ad24b01, the agent calls lookup_order first at span 26412387, gets back owner cust_4 at span 371b31be, and correctly refuses the refund at span d62617bd. 26412387371b31be463025bf71f1d62617bd

The fix is to restore a rule that lookup_order must be called and must confirm the order belongs to the requesting customer before issue_refund is invoked. bfbe27725663ced2ecd21c3e
